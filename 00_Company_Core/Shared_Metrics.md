# Shared Metrics — What Actually Matters

**Philosophy borrowed from:** Casey Winters (growth leadership at Pinterest, Eventbrite) — a marketplace is healthy when its *real-world transaction* (here: a person physically showing up) repeats, not when its app metrics spike.

---

## The North Star
### Weekly Verified Attendees Who Return (WVA-R)
> Number of users who checked in at a real event this week **and** checked in at least once more within the prior 4 weeks.

Why this metric: it fuses our two truths — the event must happen in the real world (verified check-in), and it must become a habit (return). Everything else is a supporting actor.

## The Metric Hierarchy
| Tier | Metric | Definition | Target |
|---|---|---|---|
| North Star | WVA-R | Verified attendees who returned within 4 weeks | Grow weekly |
| Outcome | Attendance Rate | Attendees ÷ RSVPs per event | > 70% |
| Outcome | Repeat Attendance Rate | Attendees with ≥2 events in 28 days | > 40% |
| Outcome | Friendship Formation | Post-event mutual "connected" marks per active user/mo | ≥ 2 |
| Habit | Streak Continuation | % of 3+ check-in streaks still alive at day 30 | > 50% |
| Trust | Safety Report Rate | Reports per 100 events | < 2 |
| Trust | P0 Resolution Time | Hours from report to action | < 24h |
| Supply | Verified Host Activation | % of approved hosts running ≥2 events/mo | > 60% |
| Density | Weekly Anchor Events | Recurring events live per campus | ≥ 30/campus |

## Anti-Metrics (Vanity — Never Optimize These)
- DAU/WAU/MAU as a goal (diagnostic only)
- Time-in-app, session length
- Total downloads or sign-ups
- Any leaderboard of "most active user on the app"

## Diagnostic Metrics (Use to Explain, Never to Celebrate)
- App opens per attendee per week (should be LOW — a healthy user opens the app to find an event, then leaves)
- Ticket volume by type (routing signal for departments)
- Funnel: discovery → RSVP → check-in (find where real-world friction lives)

## Rules Every Agent Follows
1. Every experiment and ticket states which metric it moves, and how it will be measured.
2. No metric claim without a Data/Analytics review (see 08_Data_Analytics).
3. If a feature improves an app metric while flat-lining a real-world metric, it is **killed**, not celebrated.
4. Metrics are reviewed weekly (Operating_Rituals.md → Metrics Review). Trends > single weeks.
